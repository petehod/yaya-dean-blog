Becoming a software engineer changed my approach to music. In programming, there’s a concept known as objects. These are data structures that organize information as key-value pairs. Imagine a dictionary where each word (key) has a definition (value). In code, these pairs are enclosed in curly braces {} and might look something like this:

<CodeBlock caption="Here are some details about me represented as an object. Name, age, and occupation are the keys and Dean, 25, and Software Engineer are the values.">
    ```ts
    {
        name: "Dean",
        age: 25,
        occupation: "Software Engineer"
    }
    ```
</CodeBlock>

It dawned on me that songs can be visualized as objects. Each song has a set of attributes—its keys—that define it, with corresponding values that describe those attributes. Here’s how a song might look when represented as an object:

<CodeBlock caption={`"Baby" by Justin Bieber represented as an object`}>
    ```ts
    {
        song_name: "Baby",
        artist: "Justin Bieber",
        featured_artist: "Ludacris",
        tempo: 130,
        key: "Eb Major",
        chord_progression: "Eb, C-, Ab, Bb",
        time_signature: "4/4",
        melody: ??
        // There are many more key/value pairs that could be added.
        // This is just a small subset.
    }
    ```
</CodeBlock>

## The Impact of Automation

In software development, it is easy to automate repetitive tasks. We automate these low-priority tasks to free up our mental bandwidth for more complex and creative challenges. For example, it is common to write a function that capitalizes first letter in a word, like this

<CodeBlock caption={"Writing reusable code like this makes it suprisingly easy to build powerful applications that are easy to maintain."}>
```ts
function capitalizeFirstLetter(str: string): string {
    if (!str) return str;
    return str.charAt(0).toUpperCase() + str.slice(1);
}

// In use
const title = "hello world";
const capitalizedTitle = capitalizeFirstLetter(title);
console.log(capitalizedTitle); // Output: "Hello world"

```
</CodeBlock>

## Focusing on the Essentials
James Clear, in his classic <a start target="\_blank" href="https://a.co/d/19jZtNM" style={{textDecoration: "underline", fontWeight: "bold"}}>Atomic Habits</a>, discusses a strategy he calls addition by subtraction:

> The Japanese companies looked for every point of friction in the manufacturing process and eliminated it. As they subtracted wasted effort, they added customers and revenue. Similarily, when we remove the points of friction that sap our time and energy, we can achieve more with less effort (154).

This idea ties in well with <a style={{textDecoration: "underline", fontWeight: "bold"}} target="_blank" href="https://en.wikipedia.org/wiki/Pareto_principle">_Pareto’s Principle_</a> , which says that 20% of your inputs generate 80% of your outputs. For example, 20% of beer drinkers consume 80% of all beer, and 20% of producers get 80% of the placements (although I think the producer one is even more skewed). If you’re interested, I highly recommend reading the book <a style={{textDecoration: "underline", fontWeight: "bold"}} target="\_blank" href="https://a.co/d/bHL2K6q">The 80/20 Principle</a>

In music production, this principle highlights that some inputs (keys in the object) matter a lot more than others. Here's a hot take: chord progressions, tempo, instruments DO NOT MATTER! By this I mean as long as you're selecting a high-quality input (a proven chord progression, a proven instrument, etc.) you can get away with picking things before you write any music. By automating the less critical aspects, we can dedicate our focus to the things that truly make a difference, like melody writing and dynamics.

For example, before I even touch my guitar, I’ll decide on the tempo, key, and basic chord progression. This sets the foundation for me to write banging melodies over. ### Recap

1. Songs/music are just objects with key/value pairs.
2. Some of these key/value pairs are more important than others.
3. We can automate low-priority key/value pairs by preselecting them before we write _any_ music.
4. Put all of our focus into high-priority key/value pairs (melody, dynamics, etc).

## Conclusion

Learning software development has fundamentally changed the way I approach music. It’s taught me to value efficiency and to focus my creative energy on the aspects of music that can’t be automated. By setting up an “assembly line” for guitar loop production, I’m able to streamline the process and produce music more quickly, all while ensuring that the most important part—the melody—gets the attention it deserves.
